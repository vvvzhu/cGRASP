# cGRASP Relay End-to-End Example

This directory contains a repeatable multi-node relay workflow for:

```text
Node A / Gray     fd00:1::1/64
Relay R left      fd00:1::fe/64
Relay R right     fd00:2::fe/64
Node B / Briggs   fd00:2::1/64
Relay R C-link     fd00:3::fe/64
Node C             fd00:3::1/64
Relay R D-link     fd00:4::fe/64
Node D             fd00:4::1/64
```

The runner creates unique Linux network namespaces named
`cgrasp-e2e-<run-id>-a`, `cgrasp-e2e-<run-id>-r`,
`cgrasp-e2e-<run-id>-b`, `cgrasp-e2e-<run-id>-c`, and
`cgrasp-e2e-<run-id>-d`, with four veth links.
Relay R has IPv6 forwarding enabled so unicast negotiation and synchronization
can be routed end to end. Node C is connected only to Relay R and performs a
post-cache discovery of the same Objective after Node A has populated relay
state. Node D is connected only to Relay R and sends low loop-count Discovery
and Flood traffic; these messages require more hops than their loop-count
allows, so Relay R must not forward them to Node B.

## Run

```bash
sudo ./ASA-examples/cgrasp_relay_e2e/run_relay_e2e.sh
sudo ./ASA-examples/cgrasp_relay_e2e/run_relay_e2e.sh --keep-artifacts
sudo ./ASA-examples/cgrasp_relay_e2e/run_relay_e2e.sh --verbose
sudo ./ASA-examples/cgrasp_relay_e2e/run_relay_e2e.sh --cleanup-only
```

Dependencies:

```text
root privileges, ip, Python
optional: tcpdump
```

If the process is interrupted, the shell trap removes the namespaces and stops
background packet captures. `--cleanup-only` removes any leftover
`cgrasp-e2e-*` namespaces.

## Objective

The test objective is:

```text
objective-num: 47991
objective-name: EXAMPLE_RELAY_OBJECTIVE
flags: F_DISC | F_NEG | F_SYNCH
```

Initial and expected values:

```text
Node A expected value: 40
Node B proposed value: 60
Negotiated result: 50
Node B synchronized value before test: 50
Flooded value: 70
```

## Relay Cache Key

Discovery cache entries are keyed as a normalized transaction:

```text
transaction-type = discovery
session-id
initiator locator
objective-num
```

The response is `M_RESPONSE`, but it is looked up against the original
Discovery transaction rather than keyed by the raw response message type. The
entry records incoming interface, upstream transport endpoint, objective
number, transaction type, expiry time, and response digest state.

Flood duplicate suppression is keyed separately:

```text
transaction-type = flood
session-id
initiator locator
objective-num
```

## SID, Token, and MID

cGRASP session IDs are stable inside a workflow phase:

```text
discovery_sid        = 0xa001
negotiation_sid      = 0xa002
synchronization_sid  = 0xa003
flood_sid            = 0xa004
```

CoAP MID and Token are generated per hop/exchange in the event trace. The
validator requires fresh MID/Token pairs for the relayed Discovery, forwarded
M_RESPONSE, and negotiation exchanges. Tokens are never used as cGRASP session
identifiers.

## Artifacts

Each run writes:

```text
artifacts/cgrasp_relay_e2e/<run-id>/
  node_a.log
  relay_r.log
  node_b.log
  node_c.log
  node_d.log
  events.jsonl
  summary.json
  relay_cache_snapshot.json
  result.txt
  cgrasp-relay-readable.txt
  link1.pcap / link2.pcap / link3-node-c.pcap /
  link4-low-loop-node-d.pcap when tcpdump is available
```

The validation input is `events.jsonl`, emitted by the deterministic scenario
driver. It records the intended relay decisions (loop-count, duplicate
suppression, cache lookup) and is **not** a packet-level capture. When
`tcpdump` is available, the pcap files are generated by real `cgrasp.cgrasp` API
calls in `cgrasp_api_node.py`; they are retained for manual inspection and are
the evidence of actual on-the-wire traffic. Node A calls `discover`,
`req_negotiate`, `synchronize`, and `flood`; Node B registers and listens for
the same Objective; Relay R runs the project CoAP relay.

To render existing pcap files in any run or capture directory into a
`captures/DNSSD/cgrasp-ns-readable.txt` style report:

```bash
./ASA-examples/cgrasp_relay_e2e/render_pcaps.sh \
  artifacts/cgrasp_relay_e2e/<run-id> \
  artifacts/cgrasp_relay_e2e/<run-id>/cgrasp-relay-readable.txt
```

This wrapper reuses `scripts/render_namespace_interactions.py` and requires
`tshark`.

## Troubleshooting

`exit 77` means the runner did not have root permissions for network
namespaces. `exit 127` means a required command was missing. Any validation
failure writes a JSON object with `"overall": "FAIL"` to `result.txt` and
keeps the artifact directory for inspection.
